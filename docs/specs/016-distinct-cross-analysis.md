# 016 Distinct Cross Analysis

## 목적

교차 분석 카드가 제목만 다르고 엔진 근거와 통합 설명을 반복하는 문제를 해결한다. 사용자는 각 영역에서 세 체계가 어느 방향을 얼마나 강조하는지, 왜 일치하거나 다른지 바로 구분할 수 있어야 한다.

## 문제

- 정규화 단계가 trait과 무관하게 각 엔진의 동일한 원천 근거 배열을 모든 영역에 복사한다.
- 규칙 기반 통합 설명이 trait과 실제 점수 차이를 사용하지 않고 상태명만 바꾼 동일 문장을 출력한다.
- 전문 계산 근거가 항상 노출되어 쉬운 비교보다 반복 텍스트가 먼저 보인다.

## 사용자 흐름

1. 사용자가 Quick 분석 결과의 교차 분석 영역을 본다.
2. 각 카드에서 영역명과 상태, 세 엔진의 1~5 점수 및 서로 다른 방향 설명을 바로 비교한다.
3. Prism 통합 해석에서 가장 높은 엔진과 낮은 엔진 또는 세 엔진의 공통 방향을 확인한다.
4. 전문 계산값이 필요할 때만 `계산 근거 보기`를 펼친다.

## In Scope

- 7개 trait별 낮음·균형·높음 방향 문구
- 엔진별 점수와 trait별 쉬운 설명
- Agreement / Complementary / Divergence / Insufficient별 실제 점수 기반 통합 설명
- 반복되는 전문 계산 근거의 접기 처리
- Gemini가 중복 설명을 반환할 때 결정론적 설명으로 교체
- 모바일에서 카드와 근거 펼치기 레이아웃 유지

## Out of Scope

- 기존 정규화 점수표 변경
- 사주·점성술·수비학 계산식 변경
- 기존 저장 리포트의 데이터 재계산 또는 일괄 마이그레이션
- 교차 분석 영역 수 변경

## 데이터 규칙

- 점수 1~2는 해당 trait을 낮게 강조하는 방향, 3은 두 방향의 균형, 4~5는 높게 강조하는 방향으로 설명한다.
- Agreement는 세 점수의 평균 방향과 trait별 관찰 포인트를 설명한다.
- Complementary와 Divergence는 최고점·최저점 엔진을 명시하고 어느 방향이 다른지 설명한다.
- 엔진 간 우열을 만들지 않으며 Divergence를 실패로 표현하지 않는다.
- 화면에 표시하는 점수와 상태는 기존 결정론적 `crossAnalyze` 결과만 사용한다.

## UI 규칙

- 보이는 순서는 `영역명 → 상태 → 엔진별 점수와 쉬운 방향 → Prism 통합 해석 → 계산 근거 펼치기`다.
- 동일한 원천 근거는 기본적으로 접어 카드의 핵심 비교를 방해하지 않게 한다.
- `summary`를 키보드로 조작할 수 있는 기본 `details` 요소를 사용한다.
- 색상만으로 엔진이나 상태를 구분하지 않는다.

## Acceptance Criteria

- 같은 분석의 상위 교차 카드 3개가 서로 다른 엔진별 방향 설명을 표시한다.
- 규칙 기반 `crossHighlights` 3개의 통합 설명이 서로 같지 않다.
- 각 통합 설명은 trait의 실제 점수 또는 점수 차이를 사용한다.
- 전문 계산 근거는 기본적으로 닫혀 있고 사용자가 펼칠 수 있다.
- 기존 교차 상태와 agreement 계산값은 바뀌지 않는다.
- 타입 검사, 자동 테스트, production build와 localhost 화면 검증을 통과한다.

## Test Cases

- 같은 점수 범위가 Agreement로 유지되는지 확인
- 큰 점수 차이가 Divergence로 유지되는지 확인
- stability와 creativity의 엔진별 방향 문구가 서로 다른지 확인
- Agreement와 Divergence 통합 설명이 최고·최저 또는 평균 점수를 반영하는지 확인
- fallback 교차 설명 3개가 중복되지 않는지 확인
- 결과 화면에 엔진 점수와 `계산 근거 보기`가 있는지 확인
