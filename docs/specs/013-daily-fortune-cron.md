# 013 Daily Fortune Cron

## 목적

저장된 Prism 분석을 가진 로그인 사용자가 매일 오늘의 운세를 확인할 수 있게 한다.

## 사용자 시나리오

1. 사용자는 Prism 분석을 저장한다.
2. 매일 09:00 KST에 사용자의 최신 저장 분석으로 오늘의 운세가 생성된다.
3. 로그인 사용자는 메인 화면에 들어와 저장된 오늘의 운세를 확인한다.
4. 운영자는 자동 실행을 놓친 날 인증된 주소를 수동 호출해 오늘분을 채운다.

## In Scope

- 사용자별 최신 분석 선택
- 날짜별 결정론적 운세 생성
- Vercel Cron 및 인증된 수동 실행
- Supabase 저장, 본인 조회 RLS, 메인 화면 표시

## Out of Scope

- 운세 생성 시 외부 LLM 호출
- 이메일·푸시 알림
- 사용자가 미래 날짜 운세를 미리 생성하는 기능

## 입력

- `analysis_results`의 사주·점성술·수비학 저장 결과
- 한국 표준시 기준 오늘 날짜

## 출력

- `daily_fortunes`의 사용자·날짜별 JSON 운세 한 건
- 메인 화면의 종합 점수, 집중·관계·균형 안내

## Business Rules

- 사용자별 최신 `analysis_results`를 운세 기준으로 사용한다.
- Detailed 분석이 있으면 최신 Detailed를 우선하고, 없으면 최신 Quick 분석을 사용한다.
- 운세 계산은 저장된 사주·점성술·수비학 결과와 한국 날짜를 입력으로 하는 결정론적 DB 함수가 담당한다. LLM이 날짜별 계산값을 만들지 않는다.

## 실행 흐름

1. Vercel Cron이 매일 00:00 UTC(09:00 KST)에 `/api/cron/daily-fortune`을 호출한다.
2. 서버는 `CRON_SECRET`을 검증하고 서버 전용 권한으로 생성 DB 함수를 호출한다.
3. DB 함수는 사용자별 최신 결과를 선택하고 사용자·한국 날짜 조합으로 오늘의 운세를 생성해 `daily_fortunes`에 upsert한다.
4. 로그인 사용자가 Prism에 들어오면 자신의 오늘 저장본만 표시한다.
5. 설정이 늦은 날에는 같은 Cron 주소를 인증해 한 번 수동 호출할 수 있으며, 중복 행 없이 오늘분을 갱신한다.

## 보안과 개인정보

- Cron과 저장 작업에는 서버 전용 Supabase 키만 사용한다. 브라우저에는 노출하지 않는다.
- `daily_fortunes`는 RLS를 켜고 본인 행만 조회할 수 있다.
- `analysis_results`의 기존 접근 규칙을 우회해 다른 사용자의 입력 또는 결과를 화면에 노출하지 않는다.

## Error Cases

- `CRON_SECRET` 미설정: 500과 설정 오류를 반환한다.
- Cron 인증 불일치: 401을 반환하고 DB를 변경하지 않는다.
- Supabase 조회·저장 실패: 500을 반환하고 서버 로그에 원인을 기록한다.
- 오늘 저장본 없음: 오류 대신 빈 상태 안내를 표시한다.

## Acceptance Criteria

- 인증 없는 Cron 호출은 401을 반환한다.
- 같은 사용자·날짜로 반복 실행해도 한 행만 남는다.
- 오늘 저장본은 로그인한 본인에게만 표시된다.
- 비로그인 첫 화면에도 오늘의 운세 카드와 로그인 안내가 보여 기능을 발견할 수 있다.
- 결정론적 운세 생성 테스트, RLS 테스트, typecheck, build를 통과한다.
- 실제 Supabase에서 migration 적용과 오늘분 수동 실행 결과를 확인한다.

## Test Cases

- UTC 날짜가 KST 날짜로 올바르게 변환된다.
- 같은 분석·날짜는 같은 운세를 생성한다.
- 날짜가 달라지면 운세 데이터도 달라진다.
- 최신 Detailed가 최신 Quick보다 우선된다.
- migration에 RLS, anon 권한 회수, 본인 조회 정책, 사용자·날짜 유일 제약이 있다.
- typecheck, 단위 테스트, production build가 통과한다.
