# 014 Daily Fortune On Demand

## 문제

매일 09:00 KST 생성 이후에 분석을 저장한 사용자는 도감에 결과가 있어도 당일 `daily_fortunes` 행이 없다. 기존 조회 API는 저장 행만 조회하므로 이를 “분석이 없음”으로 잘못 안내한다.

## 목표

로그인 사용자가 오늘의 운세를 열었을 때 오늘 저장본이 없고 본인 도감 분석이 있으면 즉시 오늘 운세를 생성해 보여준다.

## 실행 흐름

1. `GET /api/daily-fortune`이 본인의 오늘 저장본을 조회한다.
2. 저장본이 없으면 인증 사용자 전용 `generate_my_daily_fortune` DB 함수를 호출한다.
3. 함수는 `auth.uid()`와 일치하는 분석만 선택하고 Detailed 우선, 최신순 규칙으로 한 건을 고른다.
4. 사용자·날짜 조합으로 운세를 upsert한다.
5. API가 방금 생성한 저장본을 다시 읽어 반환한다.
6. 본인 분석도 없을 때만 기존 빈 상태를 표시한다.

## 보안

- 함수는 로그인하지 않은 호출을 거부한다.
- 함수 실행 권한은 `authenticated`에만 부여한다.
- `SECURITY DEFINER` 함수 내부에서 `auth.uid()`를 필수 검사하고 모든 조회·저장 조건에 해당 사용자 ID를 사용한다.
- `PUBLIC`과 `anon`의 실행 권한을 명시적으로 회수한다.
- 브라우저에 서버 비밀키를 노출하지 않는다.

## 인수 조건

- 오늘 운세가 없는 로그인 사용자가 도감 분석을 가지고 있으면 첫 조회에서 운세가 생성된다.
- 분석이 전혀 없는 로그인 사용자에게만 빈 상태가 표시된다.
- 다른 사용자의 분석이나 운세를 읽거나 갱신할 수 없다.
- 같은 사용자·날짜로 반복 호출해도 한 행만 유지된다.
- 기존 09:00 KST Cron 생성도 계속 동작한다.
- 타입 검사, 단위 테스트, production build, 실제 Supabase 검증을 통과한다.

## 원인 확인 기록

- 2026-09-28 운영 로그에서 현재 계정의 로그인·도감 저장·오늘 운세 조회가 모두 성공했다.
- DB 대조 결과 현재 계정은 분석 3건이 있지만 오늘 운세는 0건이었다.
- 기존 수동 생성은 다른 계정의 오늘 운세 1건만 만든 상태였다.
